## 实现约束

这些图片是视觉设计稿，示例日期、家庭成员、菜谱、票数和食材状态不代表当前云端数据。已按设计稿重构对应页面，图片和提示词作为设计依据保留。

- 首页保留今日菜单、投票和采购入口，不增加冰箱库存信息。
- 周菜单的选菜仍通过点击一条菜谱完成；删除菜单项与确认做菜消耗保持独立操作。
- 菜谱封面优先展示用户上传图片；没有图片时使用统一插画或现有占位方式。示例插画不能替代用户实际上传图片。
- 菜谱编辑保留“用完／有剩”及 AI 整理后的人工确认流程；不引入用量输入。输入长度和类别使用现有代码定义，图中的示例文字不作为规格。
- 做菜记录必须保留可单独选择多个食材批次的控件，并在每个已选批次上设置“用完／有剩”。不能将图里的食材摘要卡片当成唯一批次或默认自动选择，提交与冲突后重新确认规则沿用现有功能。
- 采购单仍按现有分组展示及勾选，不因图中的箭头新增详情页或折叠行为。
- 家庭页面保留本地体验说明，头像使用真实已选头像或现有文字占位；图中的人物头像仅供示意。成员行、设置行中的箭头不代表新增可点击功能。
- 所有文字、数字、状态、食材名称和图片由实际页面渲染。设计稿整图不放入小程序页面；需要的插画应另行生成素材。
- 小屏设备允许纵向滚动，底部按钮和弹层避开安全区域及键盘。现有加载、空状态、错误与重试反馈均应保留。
