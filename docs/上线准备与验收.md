## 已纳入代码的发布准备

- 家庭邀请、真实成员、菜谱、周菜单、投票、采购清单、个人口味档案和冰箱均通过云函数访问家庭数据，不用本地演示内容替代失败的云端请求。
- 投票由管理员创建，候选菜来自当前家庭；每位成员每场一票，服务端判断截止时间，票数来自真实投票记录。`vote.current` 和 `vote.close` 为本次新增的查询/管理动作。
- 采购单只汇总菜谱里会用完的食材，按标准化名称合并。手动项在重新生成时保留；重汇总先由用户确认；条目写入带 `expectedVersion`，并发冲突要求重新确认。修改动作在基线 payload 上增加 `weekStart`，服务端校验其对应的家庭清单 ID。
- 口味档案仅当前身份可读取和更新；新用户需主动同意协议，服务端保存 `privacyConsent.version/acceptedAt`，头像可跳过。
- 有可查看的隐私政策和用户协议，以及微信官方隐私指引入口。本文档不替代微信后台的隐私声明。
- iPhone 贴图采用保持像素与透明通道的 PNG，明确纳入手机包。
- 菜谱与菜单事务已修正为 CloudBase 支持的 `doc()` 读写。关键写入在事务内重查用户、成员和家庭状态；重复请求重放，失败整体回滚。

## 2. 集合、权限与索引

按 `cloudbase/indexes.json` 创建 14 个集合，并核对每个索引的名称、字段顺序、唯一性。已有集合不删除或重建；只补缺失索引。涉及唯一索引时先检查重复记录，不能为使部署成功而删除真实数据。

所有业务集合均设置客户端不可读、不可写的自定义规则，规则文件为 `cloudbase/database-security-rules.json`。默认的「仅创建者读写」不足以保证只能由云函数创建业务数据。服务端必须保留每次调用的身份和家庭校验。参见 [CloudBase 数据库安全规则](https://docs.cloudbase.net/database/security-rules)。

云存储头像：写入只能由当前登录用户执行；读取范围与昵称头像使用场景保持一致。只创建者可读会影响跨账号读取头像，公开读取则需要在隐私声明中说明；本版家庭页只展示称呼首字，因此无需为跨成员头像放开公开读。不要将数据库规则直接套用到头像上传存储，否则可选头像上传会失效。

## 4. 微信后台必做事项

- 在公众平台核对小程序主体、名称、图标、简介、服务类目及所需备案/资质；按后台当前要求完成。不要把昵称当作已完成的主体认证或备案。
- 填写用户隐私保护指引，与实际的头像选择、账号标识、口味档案、家庭共享、云服务及可选 AI 功能一致；确认手机上官方隐私指引能打开，未同意时不允许上传可选头像或加入家庭。
- 文本写入已接入微信 `security.msgSecCheck`，可选头像接入同步 `security.imgSecCheck`，拒绝或检查服务不可用时不写入业务内容。函数包内已声明云调用权限；需在正式环境实测权限、正常输入、被拒内容和服务异常，权限配置可能需要等待缓存生效。参见 [CloudBase 云调用权限](https://docs.cloudbase.net/faq/knowledge/cloud-call-604101-permission-error)。不能把本地模拟通过当作平台接口已验证。
- 检查用户权限拒绝、断网、云函数不可用、图片加载失败和低版本微信的行为。编译环境当前存在「开发者工具与基础库支持」警告，使用受支持的开发者工具版本完成正式预览。

本清单涉及平台/备案政策的事项以提交时微信公众平台显示的要求为准，代码检查不会替代这些人工验收。

## 5. 真机与双账号验收

当前在家人实际使用的手机和现有开发环境中，以两个真实微信账号验证：新用户同意协议；创建/邀请码加入；查看一致的成员；菜谱增改、添加/移除周菜单；管理员创建投票、双方投票且重复票被拒；一人勾采购单后另一人刷新可见；个人偏好互不串用；冰箱录入、做菜用完/有剩、报损和 AI 失败。另一位账号加入现有环境中的家庭已由用户确认，其余流程仍需实际验证。未来对外发布并迁移生产环境时，再用 iPhone、安卓和新账号重跑全部流程。

确认两个家庭之间不能互查或互写；断网后重试不重复创建、不重复投票、不错误勾选；菜单版本冲突不会覆盖家人修改；PNG 图集在手机完整显示。实际包大小取开发者工具预览或上传结果，主包须低于当前 2 MiB 限制。

## 6. 备份、发布与回滚

发布前导出生产集合备份并确认能恢复到隔离的验证环境；保管范围与家庭个人信息保护要求一致。为云函数错误率、超时、模型费用和数据库容量设置告警；定期清理已过期幂等记录，并按实际数据保留策略维护操作日志。

先运行 TypeScript 检查与全部测试，再运行 `node scripts/cloudbase/verify-runtime-config.js`、`node scripts/cloudbase/verify-index-spec.js` 和 `node scripts/cloudbase/verify-release.js --development`。开发参数只检查当前个人使用环境的代码准备情况，不要求生产迁移，也不授权公众平台发布。

按真实验收结果复制并填写 `cloudbase/release-evidence.example.json`。切换生产配置并同步 JS 后运行 `node scripts/cloudbase/verify-release.js --evidence <验收记录路径>`；未配置生产环境、缺少后台验收或主包数据时，该命令会阻止通过。

记录发布 Git 提交和云函数版本，先上传体验版供验收，再按平台流程提交审核，审核通过后由运营者选择发布。出现问题时同时回退匹配的客户端与云函数版本；数据库保持兼容，不通过删除集合回滚。
